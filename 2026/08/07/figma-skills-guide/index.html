Figma 内容操作技能详解

最近安装了两个 Figma 相关的 AI 技能，专门用于处理 Figma 内容操作和 React 到 Figma 的转换。本文详细介绍这两个技能的安装方法、使用场景及区别。

技能一：figma-content-operator

安装地址

技能描述

用于处理涉及检查、读取、创建、编辑、导出或代码映射的 Figma 内容任务，也用于将 HTML/React/Vue 等网页复制到 Figma。

核心能力

  • 读取和检查 Figma 设计文件内容
  • 创建、编辑、删除 Figma 画布元素
  • 导出设计资源
  • 将网页（HTML/React/Vue）复制到 Figma
  • 支持 Figma MCP、Drafito、Figwright

运行要求

  • Node.js 22.19+
  • npx
  • 网页复制需要本机 Chromium 浏览器
  • 依赖 Figma 画布读写时需要安装 Drafito 或 Figwright 插件

适用场景

场景 说明
修改 Figma 画布 直接操作现有 Figma 设计文件
设计系统管理 处理样式、变量、组件
批量编辑 批量修改多个设计元素
设计到代码 将 Figma 设计转换为代码
网页复制 将已有网页复制进 Figma

技能二：react-to-figma-make

安装地址

技能描述

将现有 React、Vite、Next.js、V0 或 AI Studio 页面转换为 Figma Make 可导入的 .fig 资产。

核心能力

  • 将 React 项目转换为 Figma Make 可编辑项目
  • 生成可导入的 .fig 文件
  • 保留设计系统的 CSS 变量和主题
  • 支持双入口架构（独立运行 + Figma Make 导出）
  • 生成完整的 Figma Make 元文件

运行要求

  • Node.js 环境
  • 一个 React 项目（Vite / Next.js / V0 / AI Studio）
  • 脚本依赖：pako 和 kiwi-schema

适用场景

场景 说明
React → Figma 将 React 代码转换为 Figma 设计
设计交付 生成 .fig 文件用于设计交付
双向协作 在 Figma Make 和代码编辑器之间协作
V0 项目 导入 V0 或 AI Studio 项目到 Figma

二者区别

对比项 figma-content-operator react-to-figma-make
方向 网页/设计 → Figma React代码 → Figma Make
输入 HTML/React/Vue/现有设计 React/Vite/Next.js 代码
输出 Figma 画布内容 .fig 可导入文件
操作方式 MCP + 插件直连画布 生成文件后导入
适用对象 设计师/产品经理 前端开发者
技术要求 Figwright MCP 配置 React 项目构建

简单选择指南

你有现成的网页/设计稿，想搬进 Figma？
→ figma-content-operator + Axhub 浏览器扩展

你有 React 代码，想生成 .fig 导入 Figma Make？
→ react-to-figma-make

你想直接在 Figma 上读取/编辑现有设计？
→ figma-content-operator + Figwright MCP

本地安装

将技能克隆到本地 skills 目录：

快速开始

figma-content-operator

  1. 安装 Axhub 浏览器扩展（Chrome/Edge）
  2. 在目标网页上点击扩展图标
  3. 点击”复制到 Figma”
  4. 在 Figma 中粘贴

或使用 MCP 模式：

  1. 配置 Figwright MCP
  2. 使用 doctor 检查连接
  3. 使用 relay 启动服务
  4. 开始读取/编辑 Figma 内容

react-to-figma-make

  1. 准备好你的 React 项目
  2. 分析项目结构和依赖
  3. 创建 Figma Make 兼容的双入口结构
  4. 生成 canvas.fig 文件
  5. 导入 Figma Make 编辑
